# 当前版本 v6

当前行为以 [车载语音与人工放行](TOUR_SPEECH.md) 为准：点击开始后先播欢迎词，再识别数字；1 左转 30°，2 右转 30°，停稳后巡线。每站播报后等待再次点击起步，不自动离站。下文保留 v1–v4 演进记录。

# 智能导览 v4

本目录是 `innovative-function-smart-tour` 分支的智能导览固件。巡线基础来自 2026-09-10 拉取的 GitHub `origin/integrated-line-ball-push`，提交 `dbdbd1f`；数字模型、预处理和连续确认来自 `origin/innovative-function` 的 `number recognition`。保留原有工作目录；v3 已通过 COM6 烧录并校验。

## 使用流程

1. 将小车放在图中下方分叉起点，车头朝两条支路之间的前方。白底黑线，两支路需要同时进入摄像头视野。
2. 上电等待模型自检完成和 `WAIT_DIGIT`。展示单个白纸黑字数字：连续 3 帧分数不低于 0.70，`1` 锁定左路，`2` 锁定右路；其他数字不会启动。
3. 串口出现 `ROUTE=1 LEFT` 或 `ROUTE=2 RIGHT` 后移开卡牌。识别后至少等待 2 秒，并确认连续稳定的脚下轨迹，才自动出发。这是额外的移牌时间，与拐点停留独立。
4. 在支路从斜线转入竖线的拐点，主动制动保持 2000 ms，再继续巡线。每个新拐点都停一次；新图中两个拐点的支路停两次，一个拐点的支路停一次。
5. 离开当前拐点后重新允许检测下一个拐点；脚下黑线消失时立即制动，连续 3 个新图像帧确认后停车锁定。不会启动避障或抓球。

`X`、空格或 Ctrl-C 急停并锁定。结束、急停或运行故障后必须重启并重新摆车；`F` 不能绕过数字选择，也不能在运行结束后重新启动。TFT 恢复原数字识别界面：实时摄像画面、识别框、数字、置信度和模型输入小图。选路后继续显示实时摄像画面。

## 编译和烧录

在本目录 PowerShell 执行 `./tour.ps1 build`。脚本使用本机 ESP-IDF 5.5.5，把中间文件放到英文临时目录，产物复制到 `firmware/`。

需要烧录时执行 `./tour.ps1 flash -Port 实际串口`，监视执行 `./tour.ps1 monitor -Port 实际串口`。烧录使用 app-flash；要求设备已有与本工程匹配的 0x10000、1 MB 应用分区。

## 实现和实车待验证项

- 起点数字识别用 160×120，选路后恢复原巡线 80×60，未将巡线阈值套用到不同分辨率。
- 摄像头沿用原车倒装方向：物理左侧对应原始图像 +x。Y 形连通轨迹在左右均有远端候选时，按数字选择对应路径；单支轨迹保留原最长路径追踪。
- 拐点几何角阈值降至 25°，适配图中的斜线转竖线。近端路径距离不超过 22 像素且置信度达标时暂停；急弯沿用原丢脚下线后转向、重新找线的流程，并在首次转向前补足停留。
- 2 秒从制动命令开始计算，尚未通过实车测量机械完全停稳后的停留时长。拐点触发位置、方向、曝光、线宽和实际停止距离都需要落地校准。
- 没有独立终点标记时，“黑线结束”和途中连续丢线在视觉上无法完全区分。二者都会停车；只有已完成拐点并确认末段时输出 `TOUR END`，其余输出故障。不会盲目前冲找线。
- 主机测试覆盖对称/不对称 Y 形左右选路、单直线、空白终点、数字连续确认、非 1/2 拒绝、移牌延时、路线锁定、急停锁定，以及真实模型 10 个自检样本。主机状态测试用模拟识别输出；并不证明真实卡牌识别率或实车拐点性能。

运行主机测试：`./tests/test_tour.ps1`，需要 PATH 中有 GCC。完整固件构建与主机测试通过后仍需实车验证；v3 已烧录；尚未进行落地路线验证。

2026-09-10 验证结果：ESP-IDF 5.5.5 构建成功，应用 478,304 字节，1 MB 分区剩余 54%；上述主机测试通过，真实模型自检 10/10，最大 logit 误差 0.00000572205。两秒拐点停留和摄像头实际路线运行尚未进行硬件验证。此处固件尺寸为 v1 记录。

## v2 多拐点更新

取消一次拐弯后永久关闭转向检测的限制。每次拐点停留 2000 ms，完成转向后等待至少 500 ms，并在连续 3 个新图像帧满足脚下有线、无拐角、航向误差小于 200 时重新允许下一次停车。重复使用同一帧不能解除限制；仍在弯道或丢线会重置直线确认。串口按顺序打印 TOUR CORNER 1、2 等。数字选路和终点停车锁定保持原行为。

相邻拐点之间必须有足够直线供重新确认；真实场地间距、地砖缝干扰和停止位置仍需实车验证。新增主机测试验证两个连续拐点的重新触发条件、冷却时间、旧帧不重复计数及弯道/丢线拒绝。


## v3 恢复摄像预览

复用原 `number recognition/main/camera_display.c` 的数字预览界面，去掉覆盖画面的电机遥测任务。数字识别阶段显示 160×120 相机画面与原识别叠加层；巡线阶段将原 80×60 画面旋转并放大两倍显示（最多约 10 次/秒），不改变巡线处理分辨率。显示原始图像发生在视觉标记修改之前。构建及主机回归测试通过，真实屏幕显示效果仍需现场观察。

## v4 抓球串口调试窗口

复用仓库根目录 `push_debug_viewer.py`，以 `VSTREAM,1` 握手切换到 921600，沿用 CRC、异步发送和录像。数字识别阶段发送 160×120 原始相机画面及数字/置信度；巡线阶段发送 80×60 画面、路线、拐点次数、停留倒计时、巡线误差与 PWM。数字/图像来自同一处理帧，电机和停留状态取最近控制周期快照。TFT 实时预览保留。

在仓库根目录运行：`./start_push_debug_viewer.ps1 -Port COM6 -AutoConnect`。先关闭其他串口监视器；不要使用旧的融合任务烧录入口覆盖导览固件。窗口启动导览按钮发送 F，急停发送 X；数字未确认或已锁定时启动按钮禁用。录像包含新 tour JSON 字段，可回看异常帧。
