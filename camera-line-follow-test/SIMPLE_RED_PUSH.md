# 红球→紫球连续测试

启用 `SIMPLE_BALL_TEST=ON` 与 `INTEGRATED_SIMPLE_MISSION=ON`：先循迹、避障，再自动进入简化红球→紫球任务。固件版本 `cam-course-two-v23`。
上电循迹电机保持停止，轨迹位于底部检测区时，点击“开始循迹→避障→推球”（串口 F）启动。避障回线对准后，只沿线直走和小幅纠偏，不执行路口转弯；底部检测区连续 3 帧丢线、刹停 200ms 完成后，退出循迹控制、交接编码器与电机，额外静置 500ms 后自动搜索红球。普通循迹丢线停车或急停不会触发推球。
关闭 `INTEGRATED_SIMPLE_MISSION` 可以恢复单独推球测试，按钮为“开始红球→紫球”。
复位、连接调试窗口和识别到球本身都不会启动电机。

把车、红球、上方黑色球门大致摆在同一方向，先测试短距离。

- `SEARCH_RED`：找不到红球时向右慢转，每次转向 70 ms，至少间隔 650 ms；连续 3 帧真实红球进入靠近阶段。
- `ALIGN_SHOT`：先对齐车、红球与黑色球门两条直边相交的直角点。角点使用地面几何拟合，必须是当前真实测量、置信度≥60；缺少角点时等待，不回退到区域中心。
  使用现有相机地面标定：倒装原始图像中，红球框的 top 是接近地面的边；以该边中点近似球的落地点，球门使用拟合的直角点。
  先把球靠近至转正画面的 y=60～80（原始 y=39～59）。朝向基本对准球后以调整档短距前进；过近（原始 y<39 或前向距离<130 mm）时退开，至原始 y≥44 且距离≥160 mm 后继续瞄准。
  通过短转向与横移，把球—目标连线延长到车的位置。要求球横向误差≤10 mm、目标横向误差≤20 mm，且车—球射线在目标距离上的横向偏差≤20 mm，连续 4 帧通过后直接前进。
  转向至少间隔 650 ms、连续 2 帧确认方向；横移每次 40～200 ms、至少间隔 350 ms。看不到可信球门或几何无效时停住等待，不盲目开推。
- `PUSH_RED`：沿对准后的车头方向连续直推，每帧刷新 500 ms 前进指令，A/D 基础 PWM 250，锁定起推时编码器估计的航向；速度 PI 与累计同步修正叠加后限在165～335，B轮不驱动。
  球偏离画面中心超过 40 px 时停止本次推球，不在接触球时横移重新瞄准。
- 简单推球窗口显示旋转 180° 后的正向画面。橙线从画面底部中心连到红球中心，青线从红球中心连到球门直角点，橙色虚线延伸原前进方向以显示偏差。此连线是视觉参考，画面底部中心不等同于标定后的车体原点；实际控制仍用地面坐标。记录文件保持原始坐标。
- 首帧漏球立即停止当前动作，连续 3 帧漏球永久停车。
- 直推时，红球近地面点到真实黑色球门区域的距离≤180 mm 就立即停车，红球阶段转入 `BRAKE_FOR_PURPLE`、原因 `RED_GOAL_STOP_SWITCH_PURPLE`；紫球阶段结束为 `DONE`、原因 `PURPLE_GOAL_APPROACH_STOP`，不等丢球。触发后主动短制动200ms，红球阶段总共静置至少500ms后按直推行程后退，退完再静置500ms、原地向左转并搜索紫球，紫球阶段保持停止；重复状态帧不会延长制动。测距取球前方（允许30 mm投影误差）、左右60 mm走廊内至少3个黑色像素支持的距离；近处不依赖角点拟合。
  这是门前停车，不代表已确认进球。阈值受标定和制动距离影响，需实车验证。窗口显示距离，日志 `goal.ball_gap_mm=-1` 表示无可信距离。
- 找球和推球各限 15 秒，对齐阶段不设总时限；图像超过 400 ms 视为过期。
- 视觉脉冲最长 500 ms；后退指令需每帧续期，断帧 500 ms 后自动急停；带转向的指令仍限 120 ms，即使摄像头停止出帧也不会一直行驶。
- `X`、`x`、空格或 `Emergency stop` 永久急停。`DONE` 和 `STOPPED` 均需 Reset 后重新开始。

此版本没有绕球、全局目标导航、全局场地定位。画面坐标来自倒装摄像头，
转向符号沿用原推球控制的约定，首次落地测试仍需观察实际方向。
寻球速度请求缩放为 25%，调整阶段为 50%，直推使用基础 PWM 250，仍有原电机最小启动 PWM 与编码器 PI，不能理解成恒定 25% PWM。

## 构建

```sh
idf.py -D SIMPLE_BALL_TEST=ON -D INTEGRATED_SIMPLE_MISSION=ON -D VISION_BENCHMARK=OFF -D VISION_BENCHMARK_QVGA=OFF build
```

切回原完整任务：`idf.py -D SIMPLE_BALL_TEST=OFF -D INTEGRATED_SIMPLE_MISSION=OFF -D VISION_BENCHMARK=OFF build`。
编译开关会保存在当前构建目录中；切换后需要重新烧录。

烧录：`idf.py -p /dev/cu.usbserial-0001 -b 115200 flash`（端口按电脑实际设备调整）。
调试窗口在仓库根目录运行：`python3 push_debug_viewer.py --port /dev/cu.usbserial-0001 --connect`，需要 Python、Tk 和 pyserial。
`start_push_debug_viewer.command` 是本机 macOS 便捷入口，依赖 Codex 的 Python 和本机 ESP-IDF Python 路径；其他电脑使用前述通用命令。

```

覆盖手动启动、转向、对准朝向后靠近到画面中下区域、左右站位与朝向模拟收敛、距离留空、缺失球门等待、连续直推、门前停车边界、丢球、急停、过期图像、超时和终止状态。
这不替代实际车轮方向、球门标定及落地推球测试。

球门检测允许最长边不超过最短边 8 倍，以兼容远处的透视压缩；仍检查最短边、面积、填充率、颜色和对比度。识别范围扩到完整画面内，剔除触及 3 px 边界带的截断物体；不再按中心 100×90 ROI 丢弃完整远处球门。简单推球接受置信度≥50 的真实球门或黑像素≥120，三点对齐仍需连续 4 帧确认。

简单推球调试使用 RGB565BE 原始颜色（串口预览帧率会下降，视觉控制不等待串口发送）；记录同时保存 PPM 和可精确重放的 `.rgb565` 文件。原完整任务继续用 RGB332，窗口兼容两种格式。

形状回归测试（仓库根目录）：

cc -std=c11 -Wall -Wextra -Werror -I camera-line-follow-test/tests/host_stubs -I camera-line-follow-test/main camera-line-follow-test/tests/black_marker_shape_test.c camera-line-follow-test/main/black_marker_vision.c -o /tmp/black-marker-shape-test
/tmp/black-marker-shape-test
```

远处球门最短边允许 4 px；恰为 4 px 时额外要求面积≥30 px、局部对比度≥50、填充率≥45%，长宽比在 5～8 的扁平目标也须满足上述加强条件，长宽比>8 仍剔除，以拒绝细长线条。

球门一般填充率下限改为30%；形状评分对50～85%填充率同等接受，适应透视楔形和低分辨率采样。最短边4 px 或长宽比>5时，仍加强到面积≥30、对比度≥50、填充≥45%。

直推采用与避障前进同类的级联闭环：直推速度 PI 使用 A/D 当前编码器增量均值作为共同目标（不再使用固定低速目标），再加上 A/D 从本段直推起点累计编码器行程的同步修正。两轮等行程，领先轮减 PWM、落后轮加 PWM，修正上限±25；停止、转向、横移、指令过期或里程计失效时清除同步基准。此修正补偿轮间行程差，不能直接测量轮胎打滑或视觉瞄准误差。

只有直推使用基础 PWM 250；瞄准期前移请求0.4、速度缩放0.50，每次160ms。直推不再使用旧的295 PWM堵转脉冲覆盖，以免覆盖250基础输出。

## 两轮切换

控制器的 `ball_index=0/1` 分别对应红球/紫球，状态名分别显示 `SEARCH_RED`、`PUSH_RED` 和 `SEARCH_PURPLE`、`PUSH_PURPLE`。两轮复用同一靠近/对齐/直推/180mm停车逻辑。切换时清空球门与角点跟踪，只处理当前颜色的球；红球丢失、急停或断流不会启动紫球轮。

红球门前停稳后先按直推行程后退、再次停稳，再输出一次原地左转并确认紫球；找不到时继续间歇向左搜索。每轮寻球与直推各限15秒，对齐无总超时。紫球完成后不再自动重启。
调试协议阶段改为 `SIMPLE_BALL_PUSH`，窗口兼容旧阶段名并自动把连线切换到当前颜色。

两轮状态测试（仓库根目录）：
```sh
cc -std=c11 -Wall -Wextra -Werror -I camera-line-follow-test/main camera-line-follow-test/tests/simple_two_ball_test.c camera-line-follow-test/main/simple_ball_push.c -lm -o /tmp/simple-two-ball-test
/tmp/simple-two-ball-test
```

红球门前停车后，记录直推开始至刹停的 A/D 编码器纵向行程；以 0.8 速度系数、航向纠偏后退相同行程（到位容差 8mm），停稳 500ms 再左转找紫球。仅回退直推行程，不包含前期对准时的前进。后退期间不依赖球检测，保留急停、相机失效停车和 15 秒后退上限。

直推同步加强：轮速 PI 更新阈值 50ms（20ms 控制周期下约 60ms），首次采样即纠偏；比例除数 2、积分除数 60。起推航向保持每偏 1° 修正约 3 PWM，0.5° 死区、最大 ±30，叠加轮速和累计行程同步后总 PWM 仍限 165～335。B 轮不驱动，基础 PWM 250、后退系数 0.8。

整合构建：`idf.py -D SIMPLE_BALL_TEST=ON -D INTEGRATED_SIMPLE_MISSION=ON build`。主机测试覆盖航向修正方向、跨 ±π、死区与限幅，以及双球后退转换；循迹到推球的完整路线仍需实车验证。

v20 终点恢复为连续 3 帧丢线结束：移除横线检测后的 80mm 前进及其 2 秒超时完成分支。前两帧丢线先停止当前运动，有效黑线重新出现会清零丢线计数并继续；只有避障后的 FINAL 阶段丢线才完成交接。

v21 寻球方向按球色区分：红球缺失向右搜索，紫球缺失向左搜索；红球推完后退、停稳再向左转找紫球的过渡动作保持不变。

v22 避障回线：仅确认底部黑线横向误差绝对值≤260、连续3帧，不再使用远处方向误差触发转向；偏离中心时仍可短横移找回，6秒内不能确认则停车。最终直行首次丢线即持续制动，3帧确认后制动200ms再交接推球；最后直行总计10秒仍未确认终点则制动停车，不启动推球。相机过期600ms和手动急停保持有效。

v23 普通循迹基础 PWM 180；终点直行独立保留基础170。循迹轮速 PI 在150ms采样增量≤6时，最低补偿由+30改为+40；其余PI参数及总输出150～270保持不变。
