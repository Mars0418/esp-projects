# ESP32-S3 摄像头巡线测试

该独立工程从已验证的 `camera-usb-test` 派生，使用 USB 摄像头代替四路红外传感器。
当前分支是 `camera idiot test hmx` 六点拟合版本，优先保证寻线和控制刷新率，TFT
只保留静态状态页，不持续刷新摄像头画面。

## 当前阶段

这是任务2的摄像头六点拟合巡线固件，已完成代码、编译、烧录和串口运行验证，仍需
继续进行场地参数标定。
它暂不包含超声绕障、终点判断和推球逻辑，也不会读取红外传感器。

## 图像处理

- 摄像头优先协商低分辨率 YUYV；当前实测摄像头回退到 640x480 MJPEG、15fps。
- JPEG 直接按 1/8 比例解码为 80x60 RGB565，实测视觉处理约 13fps。
- 有效 ROI 为 `x=3..76, y=12..57`，默认黑色门限为
  `R<=105, G<=105, B<=105`。
- 二值 mask 经过开闭运算并选择评分最高的连通域；与中心主体连通的边缘区域会被
  一并保留，孤立暗角不会仅凭面积获得高置信度，贴近画面边缘时置信度降为 0。
- 在近处 `y=13..24` 内取六个紧密采样带的黑线中心，最小二乘拟合局部方向。
  转向误差由近端横向偏移 65% 和拟合方向偏差 35% 组成，使车身中轴尽量贴近
  车前方最近的轨迹并与轨迹方向一致。
- 识别缓冲区仍会绘制绿色连通域、紫色六点和黄色拟合线，但当前不刷新到 TFT，
  以免将控制频率拖回约 3--4fps。

串口 `FOLLOW_STATUS` 会输出 `line`、`confidence`、`points`、`lateral`、
`heading`、`error`、`base`、`correction` 和左右轮 PWM，串口
`FRAME_STATUS` 会输出接收、处理、显示和丢帧计数。

## 安全控制

- 上电默认 `STBY=0`，电机不会自动启动。
- UART0（GPIO43/44，115200）发送 `F` 启动摄像头巡线；当前画面没有可靠识别到
  黑线时会拒绝启动。
- 发送 `X` 或空格立即停车。
- 图像超过 600ms 未更新、识别不到线或置信度不足时立即停车。
- A 为右前轮、D 为左前轮，初版使用 A/D 差速前进，B 后轮保持停止。
- 10 位 PWM 满量程为 1023；正常基础 PWM 为 280，低置信度为 220，单轮输出上限
  为 420，内轮下限为 70，最大差速修正为 75。

首次测试必须关闭 11.1V 电机电源完成烧录和串口识别检查；确认 `line=1`、
`confidence>=30` 且 `fresh=1` 后再将车轮架空、打开电机电源并发送 `F`。
当前实车方向使用 `STEERING_SIGN=-1`。

## 接线

摄像头、TFT和UART接线与 `camera-usb-test` 相同。电机接线沿用
`tb6612-motor-a-test/WIRING.md`。GPIO19/20由摄像头USB Host独占，调试必须使用板上
UART接口。
