# ESP32-S3 摄像头巡线测试

该独立工程从已验证的 `camera-usb-test` 派生，使用 USB 摄像头代替四路红外传感器，
同时在 128x160 TFT 上持续显示摄像头画面和识别叠加信息。

## 当前阶段

这是任务2的第一版低速巡线固件，已完成代码和编译验证，仍需架空测试及场地标定。
它暂不包含超声绕障、终点判断和推球逻辑，也不会读取红外传感器。

## 图像处理

- 摄像头输入：640x480 MJPEG，15fps。
- 解码图像：160x120 RGB565。
- 只分析图像上方 `x=6..153, y=5..79`，忽略下方可能拍到的车身。
- 使用每帧亮度直方图生成自适应黑线阈值，再选取面积和纵向跨度最大的连续暗色区域。
- 远观察带为 `y=10..37`，近观察带为 `y=48..77`。近端偏移和远端方向按 2:1
  融合为转向误差。
- TFT 叠加绿色总 ROI、青色观察带、红色画面中心线和黄色识别中心线。

如果黄色线没有落在实际黑线上，先调整 ROI 和阈值，不要直接增加电机速度。

## 安全控制

- 上电默认 `STBY=0`，电机不会自动启动。
- UART0（GPIO43/44，115200）发送 `F` 启动摄像头巡线；当前画面没有可靠识别到
  黑线时会拒绝启动。
- 发送 `X` 或空格立即停车。
- 图像超过 600ms 未更新、识别不到线或置信度不足时立即停车。
- A 为右前轮、D 为左前轮，初版使用 A/D 差速前进，B 后轮保持停止。
- 初始基础 PWM 为 150，低置信度降至 120，输出限制为 90..230。

首次测试必须关闭 11.1V 电机电源完成烧录和画面识别检查；确认叠加线正确后再将车轮
架空、打开电机电源并发送 `F`。若小车朝黑线反方向修正，将
`camera_line_follow.c` 中的 `STEERING_SIGN` 从 `1` 改为 `-1`。

## 接线

摄像头、TFT和UART接线与 `camera-usb-test` 相同。电机接线沿用
`tb6612-motor-a-test/WIRING.md`。GPIO19/20由摄像头USB Host独占，调试必须使用板上
UART接口。
