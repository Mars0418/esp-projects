# ESP32-S3 摄像头巡线与大弯控制

本工程位于分支 `camera-fool-test-zzh`。默认固件使用摄像头识别近端黑线和第一个大弯，
TFT 显示处理后的画面；直线及缓弯使用 A/D 前轮差速，大弯触发后定距前进，再使用
A/B/D 三轮原地旋转。

## 当前默认方案

`main/CMakeLists.txt` 默认编译以下控制链路：

- `main.c`：USB 摄像头、MJPEG 解码、任务和帧队列。
- `line_vision.c`：黑线分割、连通域、中心路径、横带误差和近端大弯识别。
- `camera_line_follow.c`：完整的巡线、拐点确认、ADVANCE 和三轮旋转状态机。
- `camera_display.c`：TFT 预览。

`camera_line_follow_simple.c` 是保留的 `TRACK/HOLD` 对照实验，不参与默认构建。切换
控制器时只允许修改 `main/CMakeLists.txt` 中这一处源文件名，避免两个实现同时链接。

当前画面为 160x120 RGB565：摄像头采集 640x480 MJPEG、15fps，JPEG 按 1/4 解码。
有效 ROI 为 `x=6..153, y=24..115`，原始图像 `y` 越大表示越远。默认黑色门限为
`R/G/B<=105`，可通过 UART 的 `RGB,r,g,b` 命令调整。

## 视觉与拐点

1. 对黑色掩码做 3x3 闭运算，再选择覆盖近端、中心且纵向跨度足够的连通域。
2. 从近端锚点沿连通域追踪中心路径，均匀生成最多 20 个路径点。
3. `y=24..47` 横带内的左右像素分布生成普通巡线误差；像素不足时回退到近段路径
   的横向和航向误差。
4. 大弯检测按路径从近到远检查局部两段拟合，返回第一个满足角度、拟合改善率和
   线段长度要求的拐点。这样同一画面出现两个弯时优先处理车辆将先到达的近弯，
   不再由全路径最小残差选到远弯。
5. 控制器要求方向一致且拐点坐标相邻的连续 3 帧才确认。确认后锁定物理方向，
   后续瞬时方向翻转不会覆盖；只跟踪距离不突然变远的同一近弯。
6. 已确认拐点在触发线附近短暂消失时，保留 300ms 观察窗口；若最后位置不超过触发
   线后方 18 像素，则按锁定方向进入 ADVANCE。远处拐点消失仍会超时回到 TRACK。

原 80x60 画面的触发坐标是 `corner_y=21`。当前视觉分辨率两倍，因此同一物理位置
必须使用 `corner_y=42`；写回 21 会落到 ROI 外，导致永远无法触发。

## 运动状态机

`TRACK -> APPROACH -> ADVANCE -> PIVOT -> REACQUIRE -> TRACK`

- `TRACK`：A/D 差速，基础 PWM 160，低置信度 PWM 150，单轮范围 140--190。
- `APPROACH`：大弯连续 3 帧确认后以基础 PWM 160 接近触发线。
- `ADVANCE`：拐点触线后，A/D 以 PWM 150 直行 1624 编码器计数，即 406 计数/圈
  的约 4 圈。10 秒未完成会记录 A/D 实际计数并进入旋转，避免无限直行。
- `PIVOT`：按锁定方向让 A/B/D 三轮以 PWM 95 原地旋转，持续 250--1200ms。
- `REACQUIRE`：继续以三轮 PWM 95 找线。第一帧发现有效且转向误差绝对值不超过
  250 的黑线时立即停车确认，避免等待期间扫过黑线；连续稳定 3 帧后恢复 TRACK，
  确认中断才继续原方向慢转。重捕不再要求 `big_turn=false`，因为车辆对准弯后摄像头
  仍可能合理地看到弯曲路径。

普通识别丢线暂时保持上一组电机命令，摄像头画面超过 600ms 未更新仍会安全停车。
发送 `X` 或空格可随时急停。实际轮位为 A=右前、D=左前、B=后轮。

## TFT 与日志

- 绿色：选中的黑线连通域
- 紫色：中心路径
- 黄色/橙色：第一个近端拐点的入弯/出弯局部线段
- 蓝色：当前拐点
- 青色：`corner_y=42` 触发线
- 灰色：普通巡线横带边界
- 白色：ROI 边界
- 红色：画面中心线
- 红色目标线由 `line_vision.c` 的 `STEERING_TARGET_X_OFFSET_PX` 控制；默认 0 即
  160 像素画面的 x=80。实车目标位置不是几何中心时，按“目标黑线 x 坐标 - 80”
  填入偏移值，横带误差、路径回退误差和屏幕目标线会同步移动。

UART0 使用 GPIO43/44、115200 baud。发送 `F` 启动，`X` 或空格停车。`FOLLOW`
每 2 秒报告状态、横带误差、实际转向误差、重捕稳定帧数、当前/锁定拐点、A/B/D
PWM 和 ADVANCE 编码器计数；
`FRAME` 每 3 秒报告帧吞吐、丢帧和帧龄。

### 交互式 RGB 阈值调节

电脑端工具 `camera_threshold_tuner.py` 会同时显示完整 160x120 RGB565 原图和固件最终
选中的 160x120 黑线连通域，并通过三个滑块实时发送 `RGB,r,g,b`。在仓库根目录运行：

```powershell
.\start_camera_threshold_tuner.ps1
```

也可以预选串口：

```powershell
.\start_camera_threshold_tuner.ps1 -Port COM15
```

连接时工具会先发送 `X` 保持电机停止，再发送 `TUNER,1`，将调参会话临时切换到
921600 baud；退出时发送 `TUNER,0`，恢复普通日志使用的 115200 baud 并释放串口。
完整 RGB565 图和二值 mask 使用带长度帧头的二进制协议，目标刷新率约 2fps。UART
可以同时收发，滑块命令不会阻止 ESP32 上传画面；同一时刻不能再打开
`idf.py monitor` 或其他串口助手。调参模式会暂停 TFT 刷新并始终保持电机停止。

### 高分辨率棋盘格标定

电脑端 `camera_extrinsic_calibrator.py` 使用独立的 `CALIB,1` 安全模式。该模式保持
全部电机停止，暂停 TFT 和巡线处理，约每秒发送一张摄像头原始 640x480 MJPEG；退出
后恢复 115200 baud。普通巡线分辨率仍是 160x120，不会长期增加视觉计算量。

横向/纵向内角数指整块标定板上的完整内角数量，不是当前画面中可见的数量。每张被
采纳的标定照片必须包含全部内角。完整操作和导出格式见仓库根目录
`CAMERA_CALIBRATION.md`。

## 构建与测试

```powershell
. 'D:\esp\tools\Microsoft.v5.4.4.PowerShell_profile.ps1'
idf.py -B build-local-5.4.4-user build
idf.py -p COM9 -B build-local-5.4.4-user flash monitor
```

首次验证顺序：

1. 关闭电机电源烧录，确认摄像头、TFT、青色触发线和日志正常。
2. 手持包含两个连续弯的图样，确认蓝色标记始终选择紫色路径上的第一个近弯。
3. 架空车轮发送 `F`，确认拐点需连续 3 帧才进入 APPROACH，触线后 A/D 先直行，
   随后三轮按锁定方向旋转；用 `X` 验证急停。
4. 落地后重点记录 `TURN CONFIRMED`、`TURN TRIGGER`、`advance=A/D` 和
   `SPIN START`。先调 `TURN_ADVANCE_COUNTS`，再调旋转 PWM 和时限。

本机及工程 VS Code 设置已关闭 ccache，避免 Windows 下缓存进程挂起。摄像头、TFT
和 UART 接线沿用 `camera-usb-test`；电机接线沿用 `tb6612-motor-a-test/WIRING.md`。
GPIO19/20 由摄像头 USB Host 独占，运行时电脑应连接板载 UART 口。
