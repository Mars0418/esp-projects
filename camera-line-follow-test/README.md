# ESP32-S3 摄像头寻球 / 球门识别

当前默认固件整合红球、白球、纯黑色四分之一圆球门识别、高分辨率视觉定位、
三轮里程计和闭环导航。全局位姿从 `(470 mm, 650 mm, -90 deg)` 开始，USB
摄像头开始传流后自动执行两球任务，不需要发送 `F`：

1. 保持静止；若红白两球都可见，选择更靠近上方球门 `(0, 0)` 的球，若只看见
   一个球则直接将它作为第一球。完全看不到球时，以 35% 速度朝上方球门方向探索。
   候选球仍用最近 10 帧中的 8 帧真实识别确认。
2. 估计球的地面坐标，以球心外 `150 mm` 为禁入区；若直达路线会经过禁入区，
   使用 `240 mm` 半径的连续圆弧绕到球后，并在移动中逐步朝向上方球门 `(0, 0)`。
3. 直接移动到距离球 `180 mm` 的球后方并开始推球，不再按固定距离触发精定位。
4. 推球期间若选中球达到 10 帧中 8 帧真实识别，立即停车并完整解码一帧 640x480
   图像做一次精确定位。向上方球门推球时，将 `UPPER=(0,0)` 用于建立全局坐标；
   向下方球门推球时，将 `LOWER=(900,0)` 作为已知地标校正位姿，不建立新原点。
   每个球成功定位一次后不再触发；单次定位等待 6 秒仍失败时，保留里程计继续推球，
   同时重新累计球的 8/10 检测，满足条件后再次停车定位，直到成功一次。
   定位成功后，静止统计 3 个真实球检测帧；球心平均横坐标位于画面中心
   `x=80` 正负 10 像素内才继续直推。球不居中、无法投影或 3 秒内无法完成确认时，
   保持车头方向以 35% 速度后退 `50 mm`，重新寻找同一个球；看到后重新绕到球后，
   看不到则朝对应球门方向慢速探索。
5. 第一球完成后返回 `(470 mm, 650 mm)`，再以低速将朝向调整为 `-45 deg`，
   控制退出误差约 7 度，满足正负 10 度要求。
6. 静止确认与第一球颜色相反的剩余球；若看不到，则以 35% 速度朝下方球门方向
   探索。上、下两个推球过程分别以球门顶点 `(0, 0)` 和 `(900, 0)` 为运动目标，
   车头始终沿球心指向对应球门顶点。
7. 本球成功完成一次精确定位后，若直线推球期间视觉球心距离对应球门顶点不超过
   `100 mm`，即判定进球；若当前帧识别不到选中的球，则暂时将球估计在车体中心
   正前方 `80 mm` 处，再做相同的距离判断。车体到达导航终点但球仍未确认进洞时，
   会后退 `50 mm` 并重新找球，不会仅凭车体到点判定成功。

普通移动速度为 60%，推球速度为 35%。球后方预留距离暂定为 `180 mm`，
到位误差为 `20 mm`。路径使用三轮全向速度分配，同时平移和转向；最后一段
从 `240 mm` 处沿球门方向接近到 `180 mm`，避免在球旁进行大角度原地旋转。

红球和白球识别都处理完整的 160x120 图像，不裁剪边缘。

绕球路径最多包含 8 个航点。中间航点在 `55 mm` 范围内连续切换，不停车；
导航将场地坐标速度转换为三个全向轮的速度，并同时闭环调整最终推球朝向。
到球后仅在航向误差仍超过约 12 度时做最后的小角度修正。

任务开始和绕球阶段不会因为看到球门而自动定位。只有正式推球期间，选中球达到
8/10 帧确认条件才会触发一次停车定位；停车 250 ms 后，等待连续 3 帧角点位姿
置信度不低于 70，再完整解码一帧 640x480。校准后由三轮编码器继续传播位姿。

`OBJECTS` 输出三类目标的检测结果；`MISSION_EXPLORE` 表示开始慢速探索；
`MISSION_PUSH_PRECISE_TRIGGER` 表示推球中满足8/10并停车；
`MISSION_PUSH_PRECISE_LOCK` 表示视觉位姿已更新；`NAV` 每 500 ms 输出导航状态、
当前位姿、目标点和剩余距离。

本工程使用 USB 摄像头完成小车循迹，不依赖红外模块。摄像头同时向视觉控制和 TFT
预览提供图像；普通线路使用脚下位置差速纠偏，急弯在脚下线路结束后按预先记录的方向
原地旋转，并在新线路重新进入脚下区域时停止。

当前固件版本：`cam-p41-ballcapturer`。

## 默认构建

`main/CMakeLists.txt` 当前测试固件编译：

- `black_marker_vision.c`：纯黑色四分之一圆球门识别，输出黑色像素质心。
- `quarter_goal_pose.c`：复用 `test_cmh` 标定，将球门直角和两轴拟合到地面坐标。
- `post_line_odometry.c`：独立读取 A/B/D 编码器，积分相对里程计。
- `post_line_navigation.c`：动态目标点控制、三轮速度 PI、视觉位姿锚定和里程计导航。
- `main.c`：三目标识别、两球任务状态机、停车确认和 640x480 单帧精定位。

- `line_vision.c`：旧巡线图像分割和路径分析（当前测试模式不调用）。
- `camera_line_follow_band.c`：保留调试状态查询接口和已验证控制参数作为参考；当前
  默认固件不初始化巡线或超声波任务，电机只由 `post_line_navigation.c` 控制。
- `camera_display.c`：128×160 ST7735 显示。

旧控制器文件仅保留作对照，不参与默认构建。

## 保留的图像与线路识别

摄像头优先工作在 640×480、MJPEG、15fps，固件按 1/4 解码为 160×120 RGB565。
高级地面投影和球门拟合的实际处理速度约为 4～5fps。

视觉 ROI 为 `x=3..76, y=0..51`，原始 `y` 越大表示离车越远：

1. 结合局部亮度对比、自适应亮度阈值和 RGB 上限生成黑线掩码，再做形态学闭运算。
   默认 RGB 上限为 `105/105/105`，用于排除赛道边缘的暗色背景。
2. 根据面积、延伸长度、脚下像素和上一帧位置选择连续黑线连通域。
3. 最近 12 行作为脚下区域。中央 1/2 用于确认线路进入，中央约 2/3 用于保持追踪。
4. 脚下横向位置取黑线最靠近车身几行的截面中心，避免线宽或远处支路掩盖真实偏差。
5. 从脚下锚点沿连通域生成有序路径。远端路径只记录急弯方向，不参与普通循迹修正。

TFT 中绿色是选中连通域，紫色是有序路径；脚下检测框会随有效/无效状态改变颜色。

## 普通循迹

实际轮位为 A=右前、D=左前、B=后轮。循迹只驱动 A/D，B 释放。

- 巡航基础 PWM：170；不再使用固定的起步加力。
- 急弯方向记录和等待阶段仍使用统一巡航 PWM 170，不设置单独的接近速度。
- 脚下横向误差使用原始纯位置 PI 控制，不使用远端线路或方向预判。
- 比例增益：180；积分除数：800；控制死区：20。
- 差速修正上限：120；每帧最多变化 24。
- 单轮前进范围：150～270。
- A、D 两轮各自使用正向限幅的编码器抗卡滞 PI：每 150ms 检查一次各轮
  是否达到其视觉指令对应的最低速度，接近停转时至少补 30 PWM，最大补 50。
  恢复转动后补偿快速衰减；控制器不输出负补偿，不强制两轮等速。

## 急弯状态机

`FOLLOW -> READY -> EDGE_BRAKE -> PIVOT -> FOLLOW`

1. 在脚下线路仍连续时，只记录远端急弯方向；普通循迹始终以脚下线路为目标。
   45°以下的连续弯（包括30°小弯）不进入急弯状态，直接由普通循迹通过。
2. 已记录方向后，脚下线路第一帧丢失时立即主动制动；第二帧仍丢失才确认
   到达拐点并直接按记录方向原地旋转。若下一帧线路恢复，则继续普通循迹。
3. 不再执行额外的 40ms 直行提交阶段，减少直角弯超过拐点的前冲距离。
4. 旋转开始 160ms 后从 `135/145` 降为 `130/140`，最大持续 1800ms。
5. 原线路已经离开脚下检测区域，因此第一条重新进入脚下宽区域的有效线路会立即令
   电机暂停；连续 2 帧仍有效即结束旋转。这避免继续转过新线后误认原来的入弯线。
6. 超时仍未找到线路会关闭循迹并停车。发送 `X` 或空格可随时急停。

## 超声波避障与终段

HC-SR04 每 80ms 测距一次，连续 3 次有效距离小于等于 120mm 时触发避障。
避障期间由状态机独占三路电机：

`FOLLOW -> WAIT_500MS -> PULSE_ALIGN -> STRAFE_LEFT -> FORWARD -> STRAFE_RIGHT_FIND_CENTER -> FINAL_FORWARD -> STOP`

1. 障碍距离确认后立即退出普通循迹，先主动制动并保持停车，总计等待 500ms。
   若脚下轨迹倾角绝对值超过 120，则朝修正方向原地转 80ms，再反向回转
   40ms，制动静置后重新读取倾角；最多执行 3 组，进入死区后再左移。
2. 复用红外版三编码器闭环向左平移，后轮等效目标为 974 计数（约 2.4 圈）。
3. A/D 前轮位置闭环直行 690 计数（约 1.7 圈）。
4. 低速向右平移；摄像头连续 2 帧确认脚下轨迹有效且横向误差不超过 260
   后主动制动。第一帧候选出现时立即制动等待第二帧，减少越过轨迹的距离。
5. 停稳后继续使用普通脚下位置 PI 循迹纠偏，但屏蔽急弯识别、转弯准备和
   原地旋转。连续 3 帧看不到脚下黑线即停车并关闭循迹。

左移、右移继续使用编码器速度 PI 和同步修正，但不再因三轮累计差值过大
强制停车；两段横移仍保留超时停车保护，直行仍保留编码器不平衡与超时保护。

## 当前导航安全操作

UART0 使用 GPIO43/44、115200 baud。默认固件不等待 `F`：USB 摄像头开始传流后
会自动行驶。发送 `X`、`x` 或空格会永久急停，必须按 Reset 才能重新开始。
首次地面测试必须让车轮落地并清空周围区域，随时准备发送急停命令。

以下 UART 命令和循迹诊断只适用于启用摄像头巡线控制器的旧测试模式。

## 巡线 UART、TFT 与诊断

UART0 使用 GPIO43/44、115200 baud：

- `F`：启动循迹。
- `X` 或空格：停车。
- `STATUS`：查看阈值和调试状态。
- `RGB,r,g,b`：修改 RGB 上限。
- `TUNER,1` / `CALIB,1`：进入图像抓取或标定模式。

`RUN` 日志每 2 秒输出循迹状态、脚下误差、纠偏值和 A/D PWM；`VIDEO` 每 3 秒输出
输入、处理、显示帧率以及解码/视觉耗时。

## 构建与烧录

本机 ESP-IDF 6.1-beta1 和 COM15 的命令如下。`flash monitor` 完成烧录后会直接
进入日志监视；摄像头开始传流后小车会自动运动，因此烧录前必须先架稳车身或摆好
场地，并准备发送急停键。

```powershell
cd C:\esp-projects-team\camera-line-follow-test
$env:PYTHONUTF8 = '1'
. C:\esp\v6.1-beta1\esp-idf\export.ps1
idf.py -B build-local-6.1-beta1 build
idf.py -B build-local-6.1-beta1 -p COM15 flash monitor
```

下面是仓库原有的 macOS 示例：

```sh
source /Users/lijin/esp-project/.toolchains/esp-idf-v5.4.4/export.sh
idf.py build
idf.py -p /dev/cu.usbserial-0001 flash
idf.py -p /dev/cu.usbserial-0001 monitor
```

同一个串口不能同时用于烧录、日志监视和阈值工具。烧录提示端口忙时，应先退出当前
monitor。

摄像头接线：5V、GND、D-→GPIO19、D+→GPIO20。TFT 与电机接线分别沿用
`camera-usb-test` 和 `tb6612-motor-a-test/WIRING.md`；GPIO19/20 由 USB Host 独占。

HC-SR04 接线：TRIG→GPIO48，ECHO→GPIO39。ECHO 必须经过 5V→3.3V 分压，
不能将 HC-SR04 的 5V ECHO 直接 ESP32-S3。编码器仍沿用红外版接线：
A=GPIO16/17、B=GPIO8/18、D=GPIO2/1。
