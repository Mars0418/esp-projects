# v6 车载语音、先欢迎后识别与 30° 选路

采用 Windows 中文 Huihui TTS 将固定讲解文字生成语音，固件内保存约 209 KB 的 8kHz/8bit 音频，播放时转换成 16kHz/16bit 单声道，从原车三合一模块的 USB 喇叭发声。运行无需网络、云端密钥或电脑音响；这不是 ESP32 上的任意文本实时合成引擎。修改文字后需要重新生成语音并编译烧录。

## 行驶与按钮

- 上电只显示摄像预览，不识别数字、不运动。喇叭就绪后点击“开始”，先完整播放欢迎词；播完才启用数字识别，欢迎词期间采集的旧帧不参与确认。
- 连续确认数字 1 后，等待 2 秒移开卡牌，再原地左转 30°；数字 2 则原地右转 30°。转向停稳后自动开始巡线，不需要第二次点击开始。
- 起点转向使用三轮编码器与现有 90 mm 底盘半径、27.5 mm 轮半径、406 计数/圈参数，三轮切向驱动；短脉冲配合制动纠偏，误差不超过 2° 且编码器静止 300 ms 才结束，10 秒未到位则锁定停车。上述角度是编码器估计，几何参数及方向沿用现有导航配置，必须实车校准，不能保证地面实际角度恰好 30°。
- 每个拐点到站后主动制动，播放该站讲解，并等待人工放行。即使语音结束、两秒经过，也不会自动转弯。点击“起步 / 继续”才离站；至少停两秒且语音结束后执行。
- “停车”发送 P，暂停当前运动；“起步 / 继续”发送 F 恢复。暂停转向时保留转向进度，不把人工等待算入转向超时。
- “Emergency stop”发送 X，锁定运动，取消剩余语音，必须重启。终点同样保持停车锁定，但完整播放结束语。
- “试听欢迎词”发送 SAY,0，仅在电机未启用时播放欢迎词，不启动小车。
- 界面显示喇叭未连接/就绪/播报中/故障。播报失败会停止运行；不得把“数据已提交 USB”当作人耳确认出声。

## 修改文字及构建

修改 `audio/texts.json` 的六段文字，然后在正常 Windows 用户终端依次执行：

```powershell
powershell.exe -NoProfile -File ./tools/generate_tour_speech.ps1
python ./tools/pack_tour_speech.py
./tour.ps1 build
./tour.ps1 flash -Port COM6
```

需要 Windows 已安装中文 Huihui 语音。生成脚本输出本地 WAV，打包脚本仅使用 Python 标准库，最终固件直接包含生成的 C 数组。USB 音频驱动来源和版本在 `components/usb_host_uac/SOURCE.md`，依据 [Espressif UAC API](https://github.com/espressif/esp-usb/blob/bc0904a6429389d2db72646c58ef626193180ec7/host/class/uac/usb_host_uac/README.md)。

## 验证边界

v5 已编译通过；主机测试覆盖两条路线播报映射、异常站点拒绝、无人工指令不能离站、最少两秒停留、播报中不能离站，以及调试窗口渲染和数据包解析。本次尚未验证车载实际出声与实车运动，需接回设备烧录后先点“试听欢迎词”。

## v6 音量与验证

USB 喇叭请求音量 100%，不支持硬件音量时记录错误但仍播放；软件播放幅度由原来的 192 系数提高到 384（约两倍，峰值限幅到 int16 范围）。界面新增起点估计角度 / 目标角度。主机测试验证欢迎之前与期间不识别、欢迎结束才开放识别、初始开始按钮、左右 30°、超调修正、停稳确认和转向超时。站点人工放行逻辑保留。实车声压、左右方向和转角仍待现场验证。
